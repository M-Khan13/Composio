Case study

One hundred apps,
researched and re-checked.

An agent read the developer docs for 100 SaaS products through Composio, extracted a structured verdict with Gemini, and cross-checked every answer against Composio's own toolkit catalogue. Then 18 of them were checked by hand. This is what held up — and what didn't.

Findings

01
Access is bimodal, not a spectrum.

4 of 10 categories are 100% self-serve. Gating concentrates almost entirely in Finance and Fintech (40%) and AI/Research (40%). A category is either wide open or it isn't — very little sits in between.

02
Gating is about who you are, not what you pay.

Of the 15 blocked apps, the leading blocker is partnership required. Only 1 is simply "contact sales" — the rest need a partnership, an approval process, or an enterprise contract.

03
Toolkit coverage tracks category age, not difficulty.

Composio covers 90% of Productivity and Project Management but only 30% of AI, Research and Media-native. The gap isn't where APIs are hard — it's where the category is new. 31 apps are self-serve, easy, and have no toolkit yet.

04
No toolkit can assume a single auth path.

54 of 100 apps accept more than one auth scheme. OAuth2 leads (62 apps) with API keys close behind (50), and both are commonly offered on the same product.

05
One field still needed a human — and verification made it worse.

Deciding whether a developer can truly self-serve credentials is a judgement about commercial posture, not a fact in the docs. The verification pass moved access backwards (-6pp), fixing 3 apps and breaking 4. Every other field improved.

Accuracy, honestly

Every app was answered twice. Pass 1 answers from search snippets only. Pass 2 fetches the real docs, cross-checks Composio's catalogue, and runs a critic that re-reads the evidence. Both use the same code path with steps switched off, so the difference is attributable to verification rather than to two different prompts. 18 apps — 90 individual field judgements — were then checked by hand.

Three things this table does not let me claim

1. access got worse (-6pp). The critic over-corrects on judgement calls — it fixed 3 apps and broke 4, mostly by flipping self-serve to gated. Verification helps on facts you can read off a page and hurts on questions about commercial intent. The fix is to stop the critic touching access, which measurement revealed and intuition would not have.

2. The composio_toolkit_exists jump is a gimme. Pass 1 never consults the catalogue, so it scores 0% by construction. It is a real capability difference, but it inflates the overall delta and is not the model getting smarter.

3. auth_methods is scored strictly. Exact set equality — truth api-key against agent api-key, oauth2 counts as a miss. That is harsh, and it is why the number is low.

The sample is deliberately unfair. It over-weights fintech, gated products, and rows whose cited evidence looked like it came from the wrong company. A random 18 would have drawn mostly easy developer tools and flattered both passes. These are worst-case figures.

How the agent works

Built with Composio's SDK for its tools and Gemini for structured extraction. Five steps per app.

Search the open web

Composio's COMPOSIO_SEARCH_WEB tool finds candidate developer docs. Tool slugs are resolved from the live catalogue at runtime, never hardcoded.

Rank, then fetch the real docs

Candidate URLs are scored for authority — docs./developer. subdomains and matching domains win — then the top pages are fetched through Composio and reduced to text.

Extract with a strict schema

Gemini returns one JSON row constrained by a response schema. Out-of-range values fall back to the conservative option, so a bad row can never break the batch.

Cross-check Composio's catalogue

Each app is looked up by slug across Composio's 1,000+ toolkits. This is near-ground-truth: a shipped toolkit proves a credential-obtainable API exists.

Re-read and criticise

A second pass re-reads the source docs and corrects fields the evidence contradicts. It changed at least one field on 22 of 100 rows.

Where a human was still required

The access field. Plaid documents its API openly and publishes a free sandbox — but production access requires approval, which makes it trial, not self-serve. Nothing on the page says so. 9 of the 18 hand-checked apps had access wrong in at least one pass.

A preflight executes one real search before any model call and aborts the run if the tools don't work — because an early version silently degraded to model memory when Composio returned 403, and produced five confident, plausible, completely unearned rows.
